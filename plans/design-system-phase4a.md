# Design system Phase 4a: brief page shell

## Goal / context
Migrate the shell of the brief page (`app/briefs/[slug]`) from the old tokens (`paper`, `ink`, `line`, `pink`, `blue`, `coverage`, `font-display`, `font-body`) to the new design system: the header (shared `components/ui/AppHeader.tsx`), the page header (eyebrow, serif title, lead), the sticky section nav, section markers, the reading column, the Explainer (key terms, TL;DR, header widgets) and the Locked panel for members-only briefs. Source of truth: `docs/design/design-system/design-system.md` (sections 2.2 Typography, 2.3 Layout, 3.3 Navigation, 3.6 Feedback, 3.8 Editorial, 4 Patterns), `docs/design/design-system/migration.md` (token map, section 3) and `docs/design/design-system/migration-prompts.md` ("Standing rules" and the "4a" prompt under Phase 4). Tokens live in `app/app-theme.css`, shared primitives in `components/ui`.

This is plan 2 of 2 for the first half of the migration. Plan 1 was `design-system-phase3` (PR 133, dashboard, directory, profile). Later plans: 4b (quotes), 4c (Q&A, votes, endorsements, contributions, feedback), 4d (sources, timeline, related briefs, coverage, contentious points, comments, footer actions), 4e (remaining modals and brief editing), then admin.

Decisions already made (migration-prompts.md "Decisions"): 1) "Covered by" dark band becomes `band-soft` (that is plan 4d, not here; `SectionHeader` must keep its `onDark` prop working until then); 2) status chips are neutral outside admin; 3) brief reading font is serif 19px, `text-reading`, in `max-w-reading`; 5) apply flow is unchanged.
Decisions made for this plan: 
- `AppHeader` gets NO `brief` page value. The brief page is not a primary nav destination (there is no list route), so it passes no `current`. Step 2 instead gives `AppHeader` a signed-out mode (Apply and Login links, logo to `/`) because the brief page is public.
- The section nav is a `<nav aria-label>` of buttons styled as underline tabs, NOT `role="tablist"`: it jumps within one page and does not switch panels, so the tab roles would be wrong. The active entry gets `aria-current="true"`. This is a deliberate departure from the literal wording of design-system.md 3.3; note it in the final Done line.
- Section nav tabs show the label only (the two-digit numbers stay in the section markers). Note it in Done.
- Page wrappers per section use `border-t border-rule` on the parchment canvas. No alternating bands, no `border-t-4`, no gradients (token map: "Remove").

Non-goals: no logic, data fetching, route, copy or behaviour changes (note bugs in the final step's Done line instead of fixing them; the only behaviour change allowed is the section nav losing its popover, see step 5); quotes (`quotes.tsx`, `quote-*.tsx`), Q&A (`qa*.tsx`), votes, endorse modals, contributions, feedback, FAQ (`faq*.tsx`), sources, timeline, CTAs, coverage (`coverage*.tsx`), related briefs, footer actions, explainer comments and contentious points (`explainer-engagement/comments.tsx`, `contentious-points.tsx`, `shared.tsx`, `index.tsx`) and every modal stay on the old tokens for later plans; `app/admin` stays old; do not touch `<body>` styles; `UsefulLikersModal`, `ReviewersModal`, `ContributeModals` and `ReviewEndorseModal` stay old even where they live in a file this plan edits.

"No mixing" rule for this plan: a component is either fully new or fully old. Where a component is shared between 4a and later areas, the step that migrates it says so and is the only step that touches it. The shared ones are: `SectionHeader` (step 3; also used by `quotes.tsx` and `brief-secondary-sections.tsx`, which pick up the new header look and keep old bodies, accepted), `HeaderChip`, `HeroChipBar`, `ContributorsList` (step 4), `TLDRList` (step 6; also used by `app/home/highlighted.tsx`), `renderRichText` and `Keyterm` (step 6; also used by FAQ).
