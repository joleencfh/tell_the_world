# Design system Phase 5a: admin shell, tab row, applications list and detail

## Goal / context
First of three plans for Phase 5 (admin). Migrate the admin shell (header, page title, "+ New brief" button, the tab row and its paging control), the Applications tab (pending list with the expandable detail card) and the "Recently approved" tab from the old tokens (`paper`, `ink`, `line`, `pink`, `blue`, `coverage`, `font-display`, `font-body`, stock `red-*`/`amber-*`/`green-*`/`blue-*`/`purple-*`/`pink-*`/`gray-*` colours, `text-[9px]`/`text-[10px]`) to the new design system. Source of truth: `docs/design/design-system/design-system.md` (3.1 Actions, 3.5 Data display: Accordion row at about line 298, StatusChip, Pagination; 3.7 Overlays: Confirm dialog at about line 334; section 4 Patterns: Moderation at about line 351 and Destructive actions at about line 353; open decision 4 "Admin density" at about line 392), `docs/design/design-system/migration.md` (token map) and `docs/design/design-system/migration-prompts.md` ("Standing rules" and the "Phase 5" prompt at about line 181). Decision 4 is settled for this phase: Inter 14px rows, 44px minimum row height, nothing under 12px. Decision 2: StatusChip may carry a tone on admin screens, always with icon and word.

Plans 5b (questions, correction proposals, FAQ answers, Q&A answers, contentious points, brief proposals, CTAs, contributor submissions, coverage, feedback, reviews, waitlist) and 5c (analytics tab, brief management leftovers, final sweep) follow, in that order; each is drafted after the previous one is merged. 4a to 4e are merged to `master` (4e is PR 138). This plan's files do not overlap the 4e areas: `app/admin/briefs/[id]/**` is already migrated and not touched here.

Decisions made for this plan (interview 2026-11-17):
- Rejecting an application uses `ConfirmDialog` (`tone="danger"`) naming the applicant, replacing the inline "Reject? Yes / No" swap (design-system.md "Destructive actions"). The server action `rejectApplication` and its call are unchanged. Approve keeps no confirmation (as today).
- The tab row keeps its 6-per-page paging and the "Previous tabs" / "More tabs" controls with their labels; it is restyled as underline tabs with new tokens and 44px targets. No behaviour change. Notes: the buttons are `<button>`s in a `<nav aria-label="Admin sections">` with `aria-current="page"` on the active one, NOT `role="tablist"` (the active tab swaps content below, but the existing markup has no tabpanel wiring and adding it is a behaviour change; note this departure in Done).
- `cards.tsx` is split first (step 1) without any style change, so 5b starts from a file under the lint limit and the application pieces migrate in their own file.

Non-goals: no logic, data fetching, route, copy or behaviour changes (note bugs in the final step's Done line); every admin server action keeps its `requireAdmin()` call untouched and `lib/` is not touched at all (do not edit `lib/admin/*`); the other tab components, `QuestionCard`, `CorrectionProposalCard`, `BriefProposalCard` and all other cards stay on the old tokens (5b); `app/admin/briefs/[id]/**` is done; do not touch `app/admin/page.tsx` (0 hits), `plans/.plan.json`, CI, ship settings or `<body>` styles. After this plan the admin screen is a mix of new shell and old cards: accepted, each card is internally consistent.

Lessons carried from 4a to 4e (CI failed on these every time; apply in every step):
- Unexecuted specs fail in CI on old-UI assumptions: read the markup of every asserted element; avoid strict-mode multi-matches (scope locators, exact names); hover-only text is `display:none` (`toBeAttached`, not `toBeVisible`); focus return can only be asserted when the opener stays mounted; prefer `data-testid` over class selectors (4e's CI round 1 failed on exactly this: a class locator for a card).
- A class string with a missing space silently drops a utility: after editing, grep changed files for fused utilities with `grep -nE "\][a-z]"` inside class strings.
- The final step sweeps `tests/` for assertions on old classes or colours.
