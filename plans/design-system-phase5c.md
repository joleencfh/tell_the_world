# Design system Phase 5c: analytics tab and the Phase 5 close-out

## Goal / context
Last of three plans for Phase 5 (admin). 5a (PR 139: shell, tab row, applications) and 5b (PR 140: moderation queues) are merged to `master`. What remains of `app/admin` on old tokens is only the Analytics tab: `app/admin/analytics-tab.tsx` (38 non-blank lines, 5 old-token hit lines; exports `AnalyticsEventRowItem`; a row with date, event type label, who and optional target) and the `AnalyticsTab` function at the bottom of `app/admin/tabs/misc.tsx` (2 hit lines: an italic empty-state paragraph "No activity recorded yet." and the list wrapper `bg-paper-raised border border-line px-5 py-1`; `Pagination` with `ADMIN_PAGE_SIZE`, param `analyticsPage`). This plan migrates them and then closes Phase 5: an acceptance spec over every admin tab, a whole-`app/admin` proof, and the docs. Source of truth: `docs/design/design-system/design-system.md` (3.5 Data display: list and key-value rows; decision 4 admin density: Inter 14px, 44px minimum row height where interactive, nothing under 12px), `docs/design/design-system/migration.md` (token map) and `docs/design/design-system/migration-prompts.md` ("Standing rules" and the "Phase 5" prompt: re-check rows at 390px and 1440px; rewrite `tests/two-ink-bold-11f-admin.spec.ts` to assert roles, text and behaviour, which 5a and 5b already did for most of it).

Facts: the 5b queue lists use `QueueItem` and friends from `app/admin/admin-shared.tsx` and a `data-testid="admin-queue-list"` list wrapper; the Applications tab wrapper has its own testid `admin-applications-list`. Analytics rows are read-only (no actions), so they are plain token list rows, not accordion rows. Analytics data can be empty on a fresh database. Phase 6 (cleanup) owns the leftovers outside admin: `app/layout.tsx`, `app/not-found.tsx`, `lib/email/brand.ts` and `components/landing/LegacyLandingPage.tsx`; do not touch them here.

Non-goals: no logic, data fetching, route, copy or behaviour changes (note bugs in the final Done line); every admin server action keeps its `requireAdmin()` call untouched and `lib/` is not touched at all (do not edit `lib/admin/*` or `lib/data/*`); `app/admin/briefs/**`, `AdminScreen.tsx`, the other tab files and all cards are not touched except for the single `AnalyticsTab` function in `tabs/misc.tsx`; do not touch `plans/.plan.json`, CI, ship settings or `<body>` styles.

Constraints for every step: Bun only (never npm, npx or node). Do NOT run Playwright (`bun run test`, `bunx playwright`): it would write throwaway rows to the real Supabase project; CI runs the suite. Verify with `bun run lint`, `bunx tsc --noEmit`, `bun run build` and greps. The runner has already copied the build env to `.env.local` in this worktree: run `bun run build` directly, never source or read env files. Edit files with the Write and Edit tools and `git mv`; avoid heredoc, `sed -i`, shell loops and `cat a b > c` pipelines (unattended sessions cannot approve them). Lint baseline: 1 error in the generated `env.d.ts` and about 195 warnings from vendored `.claude/skills` and `.github/skills`; "lint clean" means no NEW problems in files you changed. No em dashes in user-facing text or commit messages. Do not use the bare word "format" in commands or commit messages. Use only tokens and utilities from `app/app-theme.css` and primitives in `components/ui`: no raw hex, no stock Tailwind colours, no text under 12px, min 44px touch targets for interactive elements, visible `focus-ring`. Old-token grep used below (call it OLD): `(text|bg|border|ring|fill|divide)-(ink|paper|line|pink|blue|coverage)|font-display|font-body|font-extrabold|bg-black|(bg|text|border|ring)-(gray|red|blue|green|amber|yellow|purple|pink)-[0-9]|text-\[(9|10|11)px\]`. Commit each step with a message with no em dashes and no bare word "format".

Lessons carried from 4a to 5b: unexecuted specs fail in CI on old-UI assumptions (read the markup of every asserted element; use exact names and scoped locators; prefer `data-testid` over class or DOM-depth locators; hover-only text is `display:none`); a class string with a missing space silently drops a utility (grep changed files for fused utilities with `grep -nE "\][a-z]"` inside class strings).
